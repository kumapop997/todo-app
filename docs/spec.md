# ToDoアプリ 仕様書

ブラウザだけで動く、個人用の ToDo 管理アプリの仕様。
画面のラフは [main.JPG](../main.JPG)（メイン画面）と [detail.JPG](../detail.JPG)（詳細画面）。ラフと本書が食い違う場合は本書を正とする。

開発・構築の指針は [CLAUDE.md](../CLAUDE.md) を参照。

## 1. 概要・動作環境

| 項目 | 内容 |
|---|---|
| 構成 | `index.html` 1ファイル（CSS・JS を内包） |
| 起動方法 | `index.html` をブラウザで直接開く（`file://` で動作）。サーバー不要 |
| データ保存 | ブラウザの localStorage |
| 外部依存 | リッチエディタ Quill を CDN から読み込む。表示にはインターネット接続が必要 |
| 対象ブラウザ | Chrome / Edge / Firefox / Safari の最新版。動作テストは Chrome だけで行う |
| 対象画面 | PC のブラウザ（スマホでの利用は対象外） |
| 言語 | 日本語のみ |
| 日時 | すべて端末のローカルタイムゾーンで扱う |

起動するとメイン画面を表示する。

## 2. 用語

| 用語 | 意味 |
|---|---|
| ToDo | 登録する1件のやること |
| 締め切り | ToDo に設定した日時。設定しないこともできる |
| 締め切り時点 | 並び替えと区分の判定に使う時刻（3.1 参照） |
| 完了済み | [完了] を押した状態の ToDo |
| 区分 | メイン画面で一覧を分けるまとまり（期限切れ／本日中／明日まで／それ以外） |

## 3. 締め切りの扱い

### 3.1 締め切り時点

| 日時の指定 | 締め切り時点 |
|---|---|
| なし | なし |
| 日のみ | その日の 23:59:59.999 |
| 日時 | 指定した日の、指定した時:分（秒は 00） |

### 3.2 区分の判定

現在時刻を「今」として、上から順に判定する。

| 区分 | 条件 |
|---|---|
| 期限切れ | 締め切り時点が今より前 |
| 本日中 | 締め切り時点が今日のうち（まだ過ぎていない） |
| 明日まで | 締め切り時点が明日のうち |
| それ以外 | 締め切り時点が明後日以降、または締め切りなし |

例（今が 10月7日 14:00 の場合）:

| 締め切り | 区分 |
|---|---|
| 10月7日 13:00 | 期限切れ |
| 10月6日（日のみ） | 期限切れ |
| 10月7日 15:30 | 本日中 |
| 10月7日（日のみ） | 本日中（10月8日 0:00 になったら期限切れ） |
| 10月8日 9:00 | 明日まで |
| 10月9日（日のみ） | それ以外 |
| なし | それ以外 |

### 3.3 並び順

1. 締め切り時点が早い順
2. 締め切り時点が同じなら、登録（`createdAt`）が古い順
3. 締め切りなしは最後尾。その中では登録が古い順

この結果、同じ日の中では時刻指定ありが先、日のみ指定が後ろに並ぶ。

### 3.4 再判定

区分と期限切れは、画面を開いたままでも1分ごとに判定し直して再描画する（締め切りの到来や日付の変わり目に追従する）。

## 4. メイン画面

### 4.1 構成

上から順に次を配置する（ラフ準拠）。

1. 見出し「ToDoリスト」
2. [新規] ボタン
3. タブ [すべて] [未完了] [完了済]
4. [完了済を削除] ボタン（右寄せ）
5. ToDo の一覧

### 4.2 タブ

| タブ | 表示対象 | 区分 | 並び順 |
|---|---|---|---|
| すべて | 全件 | あり | 3.3 の順 |
| 未完了 | 未完了のみ | あり | 3.3 の順 |
| 完了済 | 完了済みのみ | なし | 完了した日時が新しい順 |

- [完了済] タブで完了した日時が同じ場合は、登録（`createdAt`）が古い順に並べる。
- 起動時は常に [未完了] タブを選択する（前回のタブは記憶しない）。
- 選択中のタブは見た目で区別できるようにする。

### 4.3 区分の表示

- 区分は [期限切れ] [本日中] [明日まで] [それ以外] の順に、見出しと罫線で分けて表示する。
- 罫線は、各区分の見出しの直下に `<hr>` を1本置く。一覧の中でほかの用途に `<hr>` を使わない。
- 該当する ToDo が0件の区分は、見出しと罫線ごと表示しない。
- [期限切れ] 区分の未完了 ToDo は、締め切り表示を赤字にして強調する。
- [すべて] タブでは完了済みも未完了と同じ区分・同じ並び順で混在させる。締め切りが過去の完了済みは [期限切れ] 区分に並ぶが、赤字の強調はしない。

### 4.4 一覧の行

1行に次を表示する。

| 要素 | 内容 |
|---|---|
| タイトル | クリックすると、その ToDo の詳細画面を開く。長い場合は折り返す |
| 締め切り | 4.5 の書式。締め切りなしは空欄 |
| [完了] | 未完了の行に表示。押すと完了済みにする |
| [未完了に戻す] | 完了済みの行に [完了] の代わりに表示。押すと未完了に戻す |
| [削除] | 押すと確認のうえ、その ToDo を削除する |

- 完了済みの行は、タイトルに取り消し線を付け、行全体をグレーで表示する。
- [完了] / [未完了に戻す] を押した結果、現在のタブの表示対象から外れた行は一覧から消える。

### 4.5 締め切りの表示書式

| 条件 | 表示例 |
|---|---|
| 日時指定・今年 | `10月7日 15:30` |
| 日のみ指定・今年 | `10月7日` |
| 今年以外 | `2027年1月5日 9:05` / `2027年1月5日` |
| 締め切りなし | （空欄） |

時は24時間表記でゼロ埋めなし、分は2桁ゼロ埋め。

### 4.6 [新規]

詳細画面を新規登録モードで開く。

### 4.7 削除

| 操作 | 確認メッセージ | 動作 |
|---|---|---|
| 行の [削除] | 「『（タイトル）』を削除しますか？」 | その1件を削除 |
| [完了済を削除] | 「完了済みの N 件を削除しますか？」 | 完了済みをすべて削除 |

- 確認はブラウザ標準の確認ダイアログ（`window.confirm`）で出す。
- 確認でキャンセルした場合は何もしない。
- 削除は取り消せない。
- [完了済を削除] はどのタブでも表示する。完了済みが0件のときは押せない状態（無効）にする。

### 4.8 空の状態

表示する ToDo がないときは、一覧の位置にメッセージを表示する。

| タブ | メッセージ |
|---|---|
| すべて | ToDoはありません。[新規]から登録してください。 |
| 未完了 | 未完了のToDoはありません。 |
| 完了済 | 完了済みのToDoはありません。 |

## 5. 詳細画面

ToDo の新規登録と、確認・編集を行う画面。メイン画面の上にポップアップ（モーダル）で表示する。

### 5.1 開き方

| 開き方 | 初期状態 |
|---|---|
| [新規] | タイトル空、日時「なし」、詳細空。タイトルにフォーカス |
| 一覧のタイトルをクリック | その ToDo の内容を表示。そのまま編集できる（完了済みも編集可） |

### 5.2 項目

#### タイトル

- 1行テキスト。必須。
- 100文字以内。入力欄で100文字を超える入力を受け付けない。
- 文字数は JavaScript の文字列の長さ（UTF-16 単位）で数える。多くの絵文字は2文字と数える。
- 保存時に前後の空白を取り除く。取り除いた結果が空ならエラー。

#### 日時

ラジオボタンで次の3つから1つを選ぶ。

| 選択肢 | 入力欄 |
|---|---|
| なし | なし |
| 日のみ | 日付（テキスト入力） |
| 日時 | 日付（同上）＋ 時刻（テキスト入力、1分単位） |

- 日付と時刻は、キーボードで値を直接入力する。ブラウザ標準の日付ピッカー・時刻入力（`type="date"` / `type="time"`）は使わない。
- 日付は `YYYY/MM/DD` の形式で入力する（例: `2026/10/07`）。年は4桁。月と日はゼロ埋めなし（`2026/10/7`）でもよい。
- 時刻は `HH:MM` の形式、24時間表記で入力する（例: `15:30`）。時はゼロ埋めなし（`9:05`）でもよい。分は2桁。`0:00` から `23:59` まで。
- 数字と区切りは半角。前後の空白は無視する。
- 保存した値を開き直したときは、ゼロ埋めした形（`2026/10/07`、`09:05`）で表示する。
- 選んでいない選択肢の入力欄は無効にする。無効な入力欄の値は検証しない。
- 「日のみ」「日時」を選んで入力欄が空のまま保存するとエラー。
- 形式が違う値、存在しない日付（`2026/14/30`、`2026/02/30` など）、存在しない時刻（`25:00`、`12:60` など）で保存するとエラー。
- 過去の日時も指定できる（保存後すぐ [期限切れ] に入る）。
- 選択肢を切り替えても、入力済みの日付は（入力した文字のまま）引き継ぐ。
- ラフの3つ目のラベルは「時のみ」だが、日付と時刻の両方を指定するため「日時」と表記する。

#### 詳細

- リッチエディタ（Quill）で入力する。任意。
- 使える装飾: 太字、斜体、下線、取り消し線、文字色、背景色、箇条書き（番号なし）、箇条書き（番号あり）、リンク、書式クリア。
- 画像・動画などの埋め込みはできない。
- チェックリストは使えない。Quill は行頭で `[ ] ` や `[x] ` と入力するとチェックリストに自動で変換するが、これは番号なしの箇条書きに置き換える。貼り付けた内容にチェックリストが含まれる場合も、番号なしの箇条書きに置き換える。保存データにチェックリストの指定がある場合は、ほかの許可していない書式と同じく書式を取り除き、文字だけを通常の行として表示する。いずれの場合もエラーは出さない。
- 文字数は、装飾を除いた見た目の文字数（改行を1文字として含む）で数え、2000文字以内とする。Quill が末尾に自動で付ける改行は数えない。
- エディタの下に `123 / 2000` の形式で現在の文字数を表示する。空のときは `0 / 2000`。
- 2000文字を超える入力・貼り付けは、超えた分を切り捨てる。
- 文の途中に貼り付けて2000文字を超える場合は、すでに入力済みの文字を残し、貼り付けた文字のうち入りきらない後ろの部分を切り捨てる。
- 文字数は JavaScript の文字列の長さ（UTF-16 単位）で数える。多くの絵文字は2文字と数える。上限で絵文字が半分に切れる場合は、その絵文字ごと切り捨てる。
- 貼り付けでは、上記の装飾以外の書式を取り除く。
- リンクは `http://` `https://` `mailto:` で始まるものだけ許可する。スキームの大文字と小文字は区別しない（`HTTPS://…` も許可する）。
- エディタ内のリンクをクリックすると、Quill のプレビュー（リンク先の URL の表示）が出る。プレビューに出るリンクを押すと、新しいタブで開く。
- Quill のリンク用ポップアップの文言は日本語にする: 「リンク先:」（標準の `Visit URL:`）、「編集」（`Edit`）、「削除」（`Remove`）、「リンクを入力:」（`Enter link:`）、「保存」（`Save`）。
- それ以外（`javascript:` などのスキームや、スキームのない文字列）はリンクにせず、文字のまま残す。エラーは出さない。入力・貼り付け・保存データの読み込みのいずれでも同じ扱いとする。

### 5.3 ボタン

| ボタン | 動作 |
|---|---|
| [保存] | 入力を検証し、問題がなければ保存して閉じる |
| [キャンセル] | 保存せずに閉じる |

- Esc キー、ポップアップの外側のクリックも [キャンセル] と同じ扱いとする。
- タイトル・日付・時刻の入力欄で Enter キーを押しても、保存しない（何も起きない）。保存は [保存] ボタンだけで行う。
- 詳細画面を開いている間、Tab キー / Shift+Tab キーによるフォーカスの移動は詳細画面の中だけで循環し、背後のメイン画面には移らない。
- 閉じるときに未保存の変更があれば「変更を破棄しますか？」と確認する。変更がなければ確認せずに閉じる。確認はブラウザ標準の確認ダイアログ（`window.confirm`）で出す。
- 変更の有無は、開いた時点の値（タイトル、日時の選択と入力、詳細の Delta）と現在の値を比べて判定する。入力したあと元の値に戻した場合は、変更なしとして扱う。
- 保存して閉じたあとはメイン画面に戻り、選択中のタブのまま一覧を更新する。

### 5.4 入力エラー

エラーは [保存] を押したときに判定し、該当する項目の近くに赤字で表示する。エラーがある間は保存せず、画面も閉じない。
表示したエラーは入力を直しても残り、次に [保存] を押したときに判定し直す。詳細画面を開き直したときは表示しない。

| 条件 | メッセージ |
|---|---|
| タイトルが空 | タイトルを入力してください。 |
| 「日のみ」「日時」で日付が空 | 日付を入力してください。 |
| 「日時」で時刻が空 | 時刻を入力してください。 |
| 「日のみ」「日時」で日付の形式が違う、または存在しない日付 | 日付を正しく入力してください。 |
| 「日時」で時刻の形式が違う、または存在しない時刻 | 時刻を正しく入力してください。 |

## 6. データ

### 6.1 保存先

localStorage のキー `todo-app.todos` に、次の形の JSON 文字列を保存する。

```json
{
  "version": 1,
  "todos": [
    {
      "id": "3f2b8c1e-...",
      "title": "報告書を提出する",
      "dueType": "datetime",
      "dueDate": "2026-10-07",
      "dueTime": "15:30",
      "detail": { "ops": [{ "insert": "部長に提出\n" }] },
      "completed": false,
      "completedAt": null,
      "createdAt": "2026-10-07T01:23:45.678Z",
      "updatedAt": "2026-10-07T01:23:45.678Z"
    }
  ]
}
```

### 6.2 ToDo の項目

| 項目 | 型 | 内容 |
|---|---|---|
| `id` | 文字列 | 一意な ID（`crypto.randomUUID()`） |
| `title` | 文字列 | 1〜100文字 |
| `dueType` | 文字列 | `"none"` / `"date"` / `"datetime"` |
| `dueDate` | 文字列 / null | `"YYYY-MM-DD"`（ローカル日付）。`dueType` が `"none"` なら null |
| `dueTime` | 文字列 / null | `"HH:MM"`（ローカル時刻）。`dueType` が `"datetime"` 以外なら null |
| `detail` | オブジェクト | Quill の Delta 形式。HTML 文字列では保存しない |
| `completed` | 真偽値 | 完了済みなら true |
| `completedAt` | 文字列 / null | 完了にした日時（ISO 8601）。未完了なら null |
| `createdAt` | 文字列 | 登録日時（ISO 8601） |
| `updatedAt` | 文字列 | 最終更新日時（ISO 8601） |

- 完了にすると `completed` を true、`completedAt` を現在時刻にする。未完了に戻すと false と null にする。
- 詳細画面での保存、完了の切り替えのたびに `updatedAt` を更新する。`createdAt` は変えない。

### 6.3 保存のタイミング

ToDo を変更する操作（保存、完了、未完了に戻す、削除、完了済を削除）のたびに、すぐ localStorage に書き込む。

### 6.4 異常時

| 状況 | 動作 |
|---|---|
| データがない（初回） | 空のリストで起動する |
| データが壊れていて読めない | 壊れた内容を `todo-app.todos.broken` に退避し、空のリストで起動する。画面上部に「保存データを読み込めませんでした。」と表示する |
| 書き込みに失敗（容量超過など） | 画面上部に「保存できませんでした。」と表示する。詳細画面からの保存なら、画面を閉じず入力内容を残す。一覧での操作（完了、未完了に戻す、削除、完了済を削除）なら、メモリ上の状態と一覧を操作前に戻す |
| Quill を読み込めない（オフラインなど） | 画面上部に「エディタを読み込めませんでした。インターネット接続を確認してください。」と表示する。[新規] は押せない状態（無効）にし、タイトルをクリックしても詳細画面は開かない。一覧の表示、タブの切り替え、完了、未完了に戻す、削除、完了済を削除は使える |

- 「壊れていて読めない」には、JSON として読めない場合のほか、構造が不正な場合を含む: 全体がオブジェクトでない、`version` が 1 でない、`todos` が配列でない、ToDo に 6.2 の項目が欠けている、項目の型が違う、`dueType` が 3 つの値のどれでもない。1件でも不正な ToDo があれば、全体を壊れたデータとして扱う。
- 値が範囲外の場合も、構造が不正な場合と同じく壊れたデータとして扱う: `title` が空または101文字以上、`dueType` と `dueDate` / `dueTime` の組み合わせが 6.2 に合わない、`dueDate` が `YYYY-MM-DD` の形でないか存在しない日付、`dueTime` が `HH:MM` の形でないか存在しない時刻、`completed` と `completedAt` の組み合わせが 6.2 に合わない、`createdAt` / `updatedAt` / `completedAt` が日時として読めない。
- 6.2 にない余分な項目があるだけなら、壊れたデータとはせずに読み込む。余分な項目は無視し、次の保存では書き出さない。
- 退避先の `todo-app.todos.broken` にすでに値がある場合は、上書きする。
- 退避したあと、すぐに `todo-app.todos` を空のリスト（`{"version":1,"todos":[]}`）で書き直す。
- 画面上部のメッセージには [×]（閉じる）ボタンを付け、押すと消える。時間が経っても自動では消えない。「保存できませんでした。」は、次に書き込みが成功したときにも消す。
- メッセージが同時に複数ある場合は、縦に並べてすべて表示し、それぞれに [×] を付けて個別に閉じられるようにする。同じ文言のメッセージは1つだけ表示する。

### 6.5 複数タブ

同じブラウザの別タブで ToDo が変更されたら、開いているメイン画面の一覧に反映する。詳細画面で編集中の内容は書き換えない。

編集中の ToDo が別タブで削除されたあとに [保存] を押した場合は、元の `id` と `createdAt` のまま、編集中の内容で登録し直す。完了の状態（`completed` / `completedAt`）は詳細画面で扱わない項目なので、削除される直前の状態を引き継ぐ（詳細画面を開いたあと、削除される前に別タブで完了の状態が変更されていれば、その変更後の状態）。

編集中の ToDo が別タブで変更されたあとに [保存] を押した場合は、タイトル・日時・詳細を編集中の内容で上書きする。完了の状態（`completed` / `completedAt`）は詳細画面で扱わない項目なので、別タブで変更された最新の状態を保つ。

別タブから壊れたデータ（6.4）が書き込まれた場合は、無視して今の一覧を表示し続ける。メッセージは表示せず、退避もしない。

別タブで `todo-app.todos` のキーそのものが消された場合（ブラウザのサイトデータ削除など）も、同じく無視して今の一覧を表示し続ける。次にこのタブで保存したときに、今の一覧の内容でキーを作り直す。別タブでアプリの操作によって全件が削除された場合は、空のリストが書き込まれるので、通常どおり一覧に反映する。

## 7. 受け入れ基準

実装の完了判定に使う。E2E テストはこの項目に対応させる。

### メイン画面

- [ ] 起動するとメイン画面が表示され、[未完了] タブが選択されている
- [ ] [すべて] は全件、[未完了] は未完了のみ、[完了済] は完了済みのみを表示する
- [ ] 3.2 の例の締め切りを持つ ToDo が、例の通りの区分に表示される
- [ ] 0件の区分は見出しが表示されない
- [ ] 区分の見出しの直下に罫線（`<hr>`）が1本ずつ表示される
- [ ] 同じ区分の中で締め切りが早い順に並び、同じ締め切りなら登録が古い順に並ぶ
- [ ] 同じ日なら、時刻指定ありが日のみ指定より前に並ぶ
- [ ] 締め切りなしは [それ以外] の最後尾に、登録が古い順で並ぶ
- [ ] 未完了の期限切れは締め切りが赤字で表示される
- [ ] 時刻が進んで締め切りを過ぎると、再読み込みしなくても [期限切れ] に移る
- [ ] 締め切りが 4.5 の書式で表示される
- [ ] [完了] を押すと完了済みになり、[未完了] タブから消える
- [ ] [すべて] タブで完了済みが取り消し線・グレーで同じ区分に表示される
- [ ] [未完了に戻す] を押すと未完了に戻る
- [ ] [完了済] タブは区分なしで、完了が新しい順に並ぶ
- [ ] [完了済] タブで完了した日時が同じなら、登録が古い順に並ぶ
- [ ] 行の [削除] は確認が出て、OK で削除、キャンセルで何も起きない
- [ ] [完了済を削除] は件数入りの確認が出て、OK で完了済みだけが消える
- [ ] 完了済みが0件のとき [完了済を削除] は押せない
- [ ] 表示対象が0件のとき、タブごとの空メッセージが表示される

### 詳細画面

- [ ] [新規] で空の詳細画面がポップアップで開く
- [ ] タイトルをクリックすると、その ToDo の内容が入った詳細画面が開く
- [ ] タイトルは100文字を超えて入力できない
- [ ] タイトルが空（空白のみを含む）だと保存できず、エラーが表示される
- [ ] 日時を「なし」「日のみ」「日時」のそれぞれで保存でき、開き直すと同じ内容が表示される
- [ ] 「日のみ」「日時」で未入力があると保存できず、エラーが表示される
- [ ] 存在しない日付や時刻、形式の違う値では保存できず、エラーが表示される
- [ ] 過去の日時で保存でき、[期限切れ] に表示される
- [ ] 詳細に装飾を付けて保存でき、開き直すと装飾が再現される
- [ ] 詳細の文字数カウンターが表示され、2000文字を超えて入力・貼り付けできない
- [ ] 変更なしで [キャンセル]・Esc・外側クリックをすると、確認なしで閉じる
- [ ] 変更ありで [キャンセル]・Esc・外側クリックをすると確認が出て、OK で破棄、キャンセルで編集に戻る
- [ ] 保存後、メイン画面のタブは保存前のまま
- [ ] 詳細の文字数は末尾の自動改行を数えず、空のとき `0 / 2000` と表示される
- [ ] 許可されていないリンク（`javascript:` やスキームなし）はリンクにならず、文字のまま残る
- [ ] 詳細のリンクは、クリックで出るプレビューのリンクを押すと新しいタブで開く
- [ ] スキームが大文字のリンクも許可される
- [ ] リンク用ポップアップの文言が日本語で表示される
- [ ] チェックリストは入力・貼り付けでは番号なしの箇条書きに置き換わり、保存データにあっても文字だけが表示される
- [ ] 文の途中への貼り付けで上限を超えると、貼り付けた分の後ろが切り捨てられる
- [ ] 文字数は JavaScript の文字列の長さで数えられ、絵文字が半分に切れて保存されることはない
- [ ] タイトル・日付・時刻の入力欄で Enter を押しても保存されない
- [ ] 詳細画面を開いている間、Tab キーでフォーカスが背後のメイン画面に移らない
- [ ] 入力して元の値に戻した場合は、確認なしで閉じる
- [ ] 入力エラーの表示は、入力を直しても次に [保存] を押すまで残る

### データ

- [ ] 登録・編集・完了・削除の結果が、再読み込み後も残っている
- [ ] 壊れたデータがあっても起動でき、警告が表示され、壊れた内容が退避されている
- [ ] 構造が不正なデータも、壊れたデータとして扱われる
- [ ] 書き込みに失敗すると「保存できませんでした。」が表示され、一覧での操作は操作前の状態に戻り、詳細画面は閉じずに入力が残る
- [ ] Quill を読み込めないとき、警告が表示され、[新規] は押せず詳細画面は開かないが、一覧の表示と完了・削除は使える
- [ ] 画面上部のメッセージは [×] で閉じられる
- [ ] 別タブでの変更が一覧に反映される
- [ ] 編集中の ToDo が別タブで削除されても、[保存] すると同じ ID で登録し直される
- [ ] 別タブで削除された ToDo を登録し直すとき、完了の状態は削除される直前のまま引き継がれる
- [ ] 値が範囲外のデータは壊れたデータとして扱われ、余分な項目があるだけのデータは読み込まれる
- [ ] 退避先がすでにあれば上書きされ、退避後は空のリストが保存される
- [ ] 画面上部のメッセージが複数あるとき、すべて並んで表示され、個別に閉じられる
- [ ] 編集中の ToDo が別タブで変更されても、[保存] すると入力項目だけが上書きされ、完了の状態は保たれる
- [ ] 別タブから壊れたデータが書き込まれても、一覧は変わらない
- [ ] 別タブで保存データのキーが消されても一覧は変わらず、次の保存でキーが作り直される

### 表示

- [ ] PC 幅で、横スクロールなしに操作できる
- [ ] タイトルや詳細に HTML タグを入力しても、文字としてそのまま表示される

## 8. 対象外

次は今回の範囲に含めない。

- スマホでの利用（スマホ幅向けのレイアウト、タッチ操作）
- ブラウザ標準の日付ピッカー・時刻入力
- 画像・ファイルの添付
- 繰り返し設定、通知・リマインダー
- タグ、カテゴリ、優先度、検索
- 手動での並べ替え
- エクスポート／インポート、複数端末間の同期
- 削除の取り消し（Undo）
- オフラインでの詳細編集（Quill を CDN から読み込むため）
- 日本語以外の言語、ダークモード
