# ToDoアプリ テストケース

[spec.md](spec.md) の仕様を、合否が機械的に決まる単位まで分解したテストケースの一覧。
Playwright の E2E テストはこの一覧の ID と 1 対 1 で対応させる（テスト名の先頭に ID を付ける）。

## 1. この文書の位置づけ

- **完成の判定**: 3 章の全ケースが合格していること。1 件でも失敗・スキップがあれば未完成とする。
- 仕様は spec.md が正。本書と食い違う場合は spec.md に従い、本書を直す。
- 仕様や受け入れ基準を変えるときは、同じ変更で本書と対応するテストも直す。
- 5 章（テストしない項目）と 6 章（未確定事項）は、完成の判定に含めない。

## 2. 共通の前提

### 2.1 実行条件

| 項目 | 内容 |
|---|---|
| 開き方 | `index.html` を `file://` で開く。開発サーバーは立てない |
| ブラウザ | Chrome（Playwright の Chromium）だけで実行する。実行時間を抑えるため、ほかのブラウザでは実行しない |
| 画面幅 | PC 幅（1280×800）で実行する。スマホでの利用は対象外なので、スマホ幅では実行しない |
| タイムゾーン | `Asia/Tokyo`（ケースで指定がある場合を除く） |
| 現在時刻 | Playwright の clock で固定する。指定がなければ **T0 = 2026年10月7日 14:00:00**（ローカル時刻。ISO では `2026-10-07T05:00:00.000Z`） |
| 開始時の状態 | 各ケースの開始時に localStorage を空にする |
| データの用意 | 「前提」のデータは、ページを開く前に localStorage のキー `todo-app.todos` へ spec.md 6 章の形式で直接入れる。「操作」に書いた登録だけ画面から行う |
| 時間を進める | clock を進める。実時間の待機や `sleep` は使わない |

### 2.2 全ケース共通の合格条件

各ケースの期待結果に加えて、次を満たすこと。

- ページ内で例外が発生していない（`pageerror` が 0 件）。
- コンソールにエラーが出ていない（`console.error` が 0 件）。ERR-23〜30 では、遮断した Quill の読み込み失敗そのもののログだけ除く。

### 2.3 データの書き方

「前提」欄の ToDo は次の記法で書く。

| 記法 | 意味 |
|---|---|
| `A[10/7 15:30]` | タイトル A、日時指定（`dueType: "datetime"`）。年を省いたら 2026 年 |
| `A[10/7]` | タイトル A、日のみ指定（`dueType: "date"`） |
| `A[なし]` | タイトル A、締め切りなし（`dueType: "none"`） |
| `✓A[…]` | 完了済み。`completedAt` は指定がなければ T0 の 1 時間前 |

- 指定がなければ未完了、詳細は空（`{"ops":[{"insert":"\n"}]}`）。
- `createdAt` は、指定がなければ「前提」に書いた順に古い（2026-10-01 00:00 から 1 分刻み）。
- localStorage の `todos` 配列には、「前提」に書いた順とは逆順に入れる（並び替えが配列順に頼っていないことを確かめるため）。

### 2.4 判定の取り決め

実装とテストの両方がこの取り決めに従う。

| 対象 | 判定方法 |
|---|---|
| 要素の特定 | 役割（role）と表示文言で特定する。ボタンは `button` と表示名、タブは `role="tab"`、詳細画面は `role="dialog"`、区分の見出しは見出し要素（`heading`）とする |
| 選択中のタブ | `aria-selected="true"`。選択していないタブは `"false"` |
| 無効（押せない） | 要素に `disabled` が付いている |
| 確認ダイアログ | Playwright の `dialog` イベントで受ける。種類が `confirm` で、メッセージが期待の文言と完全に一致すること |
| 確認が出ない | 操作の間に `dialog` イベントが 1 度も発生しない |
| 赤字 | 計算後の文字色（`color`）で、赤成分が緑成分・青成分のどちらよりも大きい |
| グレー | 計算後の文字色で、赤・緑・青の成分の差がそれぞれ 16 以下。かつ未完了の行のタイトルの色と異なる |
| 取り消し線 | 計算後の `text-decoration-line` に `line-through` を含む |
| 横スクロールなし | `document.documentElement.scrollWidth <= clientWidth` |
| 保存内容 | `localStorage.getItem("todo-app.todos")` を `JSON.parse` した値 |
| 画面上部のメッセージ | 見出し「ToDoリスト」より上か直下にあり、[×] ボタン（表示名「閉じる」）を持つ |
| 書き込み失敗の再現 | ページを開いたあと `Storage.prototype.setItem` を `QuotaExceededError` を投げる関数に差し替える |
| Quill 読み込み失敗の再現 | ページを開く前に、`file://` 以外へのリクエストをすべて失敗させる |
| 貼り付け | エディタにフォーカスを置き、`text/html` と `text/plain` を持つ `paste` イベントを発生させる |
| 別タブ | 同じブラウザコンテキストで `index.html` を 2 ページ開く（ページ1・ページ2） |
| 一覧の並び | 一覧に表示されたタイトルを上から順に取り出した配列で比べる |

## 5. テストしない項目

次はテストせず、完成の判定にも含めない。人が確かめる項目は残っていない。

| 項目 | 理由 |
|---|---|
| ラフ（`main.JPG` / `detail.JPG`）との見た目の近さ、余白や配色の印象 | 合否の基準を定められない |
| Chrome 以外の対象ブラウザ（Edge / Firefox / Safari）での動作 | 実行時間が長くなるのを避けるため、動作テストは Chrome だけで行う |
| スマホでの利用、ブラウザ標準の日付ピッカー・時刻入力 | 仕様の対象外（spec.md 8 章） |
